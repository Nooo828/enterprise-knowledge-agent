# 阶段复盘与下一步

本轮最难的问题是兼容服务没有严格遵守关闭并行工具提议的参数。初始实现要求每次只有一个动作，首个检索后就因模型提出两项读取而停止；真实日志揭示了这个问题，离线测试无法发现。修复方案只执行第一项提议并把实际观察交回模型，保留执行上限与可追踪性，而不是伪造其余动作已成功。

第二个取舍是证据真实性与自由回答的平衡。采用原子片段完整引用和抽取式答案，并阻止在已发现的同规则版本未读完时回答，容易解释和验证；代价是答案不够自然，对同义改写的规则文本也可能保守判为冲突。它适合本题小型合成资料，不应直接宣称可覆盖任意企业制度。

本轮观察说明只测happy path不足：同一问题换文档、30改45、工具一次失败与持续失败，分别揭示不同决策结果；保留初次失败材料比仅提交最终成功截图更可核查。这是本轮实现中得到的工程观察，不冒充候选人的个人学习陈述。

优先下一步是由候选人亲自复跑、解释关键代码并记录个人修改；技术上扩展适用范围/制度优先级的明确数据契约、更多未见问法与否定规则、提示注入/错误引用挑战集，再评估是否需要语义检索和独立相关性审查。没有为框架名称、多Agent或UI额外增加复杂度。

未完成项：数字题号待候选人从考试平台补齐；没有生产权限系统和线上部署；未做大样本/跨模型质量评估或独立人工语义评分。核心CLI、两种运行模式、六项必验收及文档替换检查已实现并有真实运行材料。
