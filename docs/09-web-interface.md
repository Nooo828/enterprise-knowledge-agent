# 可视化操作界面

新增本地网页工作台，复用原来的Agent与引用校验，不需要Node.js、前端编译或新增Python依赖。

## 启动

在项目根目录打开PowerShell：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.xiaoying_agent.web
```

浏览器访问 http://127.0.0.1:8765 。保持这个终端运行，Ctrl+C结束。端口占用时使用 `--port 8766` 并访问对应地址。只监听本机127.0.0.1；当前不提供互联网部署或多用户账号权限。

## 操作与功能

1. 问答工作台：选择11种场景之一，填写问题。默认离线演示，无需密钥且明确标记Mock边界；选择真实模型则从本机.env读取配置并产生服务商调用费用。网页从不接收或显示API密钥。
2. 运行设置：最多1..30步，可设置检索/读取的一次或持续故障；可传入最多10条JSON格式历史。场景会预填对应问题、资料、故障和上限，仍可手动调整。
3. 答案与依据：显示任务状态、抽取式答案、文档ID、版本日期、完整引用、资料缺口和追问。冲突时列出双方而不自行选择新版本。
4. 执行日志：执行中约每550毫秒读取一次本地任务状态；每条记录展示步骤、动作、参数、实际观察、公开依据和下一动作。参数和完整返回可展开；支持仅看错误。单独显示模型调用、工具调用、耗时和最终状态，不展示模型内部思维过程。
5. 知识资料：编辑文档版本日期及原文，再回到问答页运行。修改仅用于本次运行快照，不覆盖data/原始资料。选择“明确答案”，把D01的30天改为60天，可观察引用和答案变化。
6. 运行记录：保留本次服务最近20项任务；点击恢复对应输入、资料、结果和日志。重启服务会清空记录，可用“下载完整记录”导出包含资料快照、Trace及事件的JSON。
7. 继续追问：把选中的上一轮问题和答案加入历史，填写下一问题再运行。历史只帮助确定主题，答案仍需本轮工具证据。
8. 停止运行：协作停止，不强行中断进行中的网络请求。点击后当前模型调用结束才生效，返回incomplete/user_cancelled；单次模型请求的45秒超时仍有效。

## 执行与日志结构

前端为原生HTML/CSS/JavaScript；web.py基于标准库ThreadingHTTPServer提供静态文件和JSON接口。JobStore最多并发2项任务，仅保留最近20项。每项任务创建独立provider与资料快照，避免故障状态和证据串线。

Agent.run新增可选on_event与should_stop参数，CLI默认行为不变。事件为model_start、step、model_error、cancelled、completed；step.payload与该次Agent trace条目一致。观察回调拿到深拷贝，回调异常不会改变Agent执行结果。网页日志通过这些真实执行事件生成，不是预设动画。

接口：GET /api/config（只返回配置是否存在、模型名和合成场景）、POST /api/jobs、GET /api/jobs、GET /api/jobs/{id}、POST /api/jobs/{id}/cancel。静态资源采用固定白名单，不能通过网址读取.env、源码或登录配置；限制同源访问、Host、JSON请求类型和128KB请求体；返回CSP与no-store头。页面使用textContent展示问题/资料/日志，避免将文档内容当HTML执行。这些本机保护不等同生产安全评估。

## 验证

当前66项pytest通过（原CLI42项，加网页接口和事件相关24项），结果见 ../examples/tests-final.txt。覆盖11组业务场景经HTTP执行、编辑资料后答案变化、事件与Trace一致、缺配置不回退Mock、静态文件越界拒绝、跨站拒绝、并发限制和停止运行。

浏览器实操已验证离线冲突、编辑30→60天、真实模型根据60天原文回答、真实冲突查证和补检优先级、仅看错误日志、历史恢复、下载记录及390px宽度无横向溢出。实际下载的真实模型冲突记录见 ../examples/web/exported-live-conflict.json；网页运行快照与核对结果见 ../examples/web/validation.json。截图见 ../examples/web/screenshots/desktop.png 和 ../examples/web/screenshots/mobile.png。

这些网页验证不覆盖所有浏览器，也不声称有企业级访问控制。旧CLI验收与本轮UI验证分别留存。
